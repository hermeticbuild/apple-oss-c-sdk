# compiler-rt linker directive evidence

Compile the pinned LLVM `apple_versioning.c` with the verified LLVM prebuilt and
the public-source C installation. The extractor reads each Mach-O object's
defined external names and verifies the generated header receipts for every
include. It emits a sorted JSON report for arm64 and x86_64. The report records
directives generated by the source file. Shipping `libcompiler_rt` still needs
its architecture-specific export selection and historical deployment policy.
[LLVM versioning source](https://github.com/llvm/llvm-project/blob/85ac560262434c9ccfc0c183ec22d4138ed647fb/compiler-rt/lib/builtins/apple_versioning.c)

With `LLVM` set to the prepared official LLVM bundle and `C_INSTALL` to the
generated macOS C installation, run from the repository root.

```sh
work=$(mktemp -d)
curl -fsSLo "$work/apple_versioning.c" \
  https://raw.githubusercontent.com/llvm/llvm-project/85ac560262434c9ccfc0c183ec22d4138ed647fb/compiler-rt/lib/builtins/apple_versioning.c
python3 -m tools.libsystem.compiler_rt_directives --llvm "$LLVM" \
  --c-install "$C_INSTALL" --source "$work/apple_versioning.c" \
  > "$work/compiler-rt-directives.json"
```

Both source objects contain 318 directives. Compiling Apple's public
`clang-800.0.42.1` copy independently yields the same names on both targets.
Its public Darwin exclusion files describe selection for Clang's deployable
builtins archives. That selection is for a different artifact from the
`libcompiler_rt.dylib` reexported by libSystem.
[Apple versioning source](https://github.com/apple-oss-distributions/clang/blob/0f08e8e398e3b878a219e71587c56448bdff4909/src/projects/compiler-rt/lib/builtins/apple_versioning.c)
· [Apple Darwin exclusion rules](https://github.com/apple-oss-distributions/clang/blob/0f08e8e398e3b878a219e71587c56448bdff4909/src/projects/compiler-rt/lib/builtins/Darwin-excludes/README.TXT)

## macOS 26.5 comparison

The reference SDK is used for this comparison. The extractor accepts only
the pinned sources, their generated C headers, and the locked LLVM tools.

| Target | Source directives | Reference directives | Shared | Reference only | Source only |
| --- | ---: | ---: | ---: | ---: | ---: |
| arm64 | 318 | 318 | 264 | 54 | 54 |
| x86_64 | 318 | 358 | 304 | 54 | 14 |

The same 54 reference-only rows remain open on both architectures.

- Nine hides cover `___chkstk_darwin` for macOS 10.6 through 10.14. Apple
  publishes its current pthread implementation and the host arm64e export
  trie confirms the reexport from `libcompiler_rt`. Those sources give the
  implementation and provider, without the historical selectors.
  [Apple pthread assembly](https://github.com/apple-oss-distributions/libpthread/blob/1f4f5265b319111142f1bf3a27d4484ef5a98314/src/pthread_asm.s)
- The other 45 rows are 10.6 through 10.10 hides for three half-precision
  conversions and six C atomic flag and fence functions. Public LLVM and
  Apple source provide implementations, and the versioning files leave
  their shipping selectors open.
  [LLVM half conversion](https://github.com/llvm/llvm-project/blob/85ac560262434c9ccfc0c183ec22d4138ed647fb/compiler-rt/lib/builtins/extendhfsf2.c)
  · [Apple atomic flag implementation](https://github.com/apple-oss-distributions/clang/blob/0f08e8e398e3b878a219e71587c56448bdff4909/src/projects/compiler-rt/lib/builtins/atomic_flag_clear.c)

All source-only rows select 10.4 or 10.5. The matching Apple shipping filter
remains open. Every observed selector predates the qualified deployment
minimum of macOS 11.0. A fixture with the extracted `___divdc3` hide directives
linked with LLVM LLD at 11.0 and 26.5 on both targets. The same fixture rejected
the import at 10.5 on x86_64. Keep the extraction report as source evidence and
leave production TBD emission to a separately reviewed selection.
