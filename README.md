# Apple OSS macOS C headers (prototype)

This repository builds a standalone C header tree for macOS arm64 and x86_64
cross-compilation from pinned Apple OSS submodules and local compatibility
recipes. Each qualified Apple install command contributes its public headers.
The SDK coverage probes under `tools/` measure the result. Clang resource
headers, libc++, the libunwind runtime, libraries, and frameworks come from
separate toolchain inputs.
The retained Apple OSS `libunwind` submodule supplies only
`mach-o/compact_unwind_encoding.h`, a Mach-O format header named by Zig's C
probe. The installer does not publish `unwind.h`, `libunwind.h`, or
`__libunwind_config.h`; those remain toolchain-owned.

## Generate the C installation

Run from the repository root on macOS. The installer uses Make, CMake, Ninja,
Python 3, Perl, system MIG, and standard command line tools such as `ed`,
`unifdef`, `awk`, `realpath`, and `shasum`. CMake and Ninja default to tools on
`PATH` and can be set with `CMAKE` and `NINJA`. Supply the pinned LLVM 23.1.2
minimal prebuilt Clang. The resolver command below uses hermetic-llvm and Bazel.

```sh
LLVM_REPO=/absolute/path/to/hermetic-llvm
LLVM_CLANG=$(python3 -m tools.toolchain.resolve_clang --llvm-repo "$LLVM_REPO")

git submodule update --init --recursive
make install CLANG="$LLVM_CLANG" OUT=/tmp/apple-oss-c-headers
```

The output directory must be new. The installer stages each upstream install
separately, merges public headers, and compares MIG output across both targets.
It emits one `header-manifest.tsv` with each header's origin, producer,
selection rule, inputs, transformation, and SHA-256.
See [the recipes](recipes/README.md) for the production steps.

## Test the C installation

Run the suite against the tree generated by `make install`:

```sh
make test CLANG="$LLVM_CLANG" OUT=/tmp/apple-oss-c-headers
```

See [the tests](tests/README.md) for the checks and host requirements.
